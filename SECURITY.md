# Security policy

Report vulnerabilities privately through the repository’s **Security → Report a vulnerability** feature when enabled. If that feature is unavailable, contact a project maintainer privately before disclosing sensitive details. Do not post credentials, private browser backups or a working exploit against another person’s data in a public issue.

Include the affected version/content release, a small reproduction, likely impact and any proposed mitigation. Keep reports limited to systems you are authorized to test. Do not run load tests against the hosted site.

The application is intended to keep learner progress in the browser and support portable backups. Backups can contain personal study history; review them before sharing. Any future synchronization feature needs a separate privacy/security review. Do not treat local storage as encrypted storage.

Code and content releases are versioned separately. Security fixes should identify affected application versions and content schema/release compatibility. A withdrawn content item retains a history/tombstone record without being offered for new learning.

Until a public stable release policy is announced, maintainers prioritize the current development version. This file does not promise a response time or security-support window that has not been established.

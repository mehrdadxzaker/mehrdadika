# Vocabulary localization: Portuguese and Spanish

The first Portuguese locale is `pt-BR`: English vocabulary explained in Brazilian Portuguese for Portuguese-speaking learners. European Portuguese (`pt-PT`) can be added as a distinct locale after its wording is reviewed; it should not be silently relabeled as the same translation.

`content/locales/pt-BR.json` and `content/locales/es-419.json` are translation overlays for Brazilian Portuguese and the first Latin American Spanish edition. Both teach English. Each contains:

- All 127 lexical entries and 128 meanings, including the 50-word cooking foundation.
- 256 translated examples and 381 translated collocations, aligned to the original English.
- 127 native usage notes, including distinctions such as `library`/`bookshop`, `recipe`/`receipt`, `bake`/`roast` and the two meanings of `pressure`.
- Native labels for all 32 subject categories, 348 subcategories and six discovery groups.

This is an **AI-assisted editorial preview**. Independent native-language and specialist review have not been recorded. Clinical and engineering material remains introductory vocabulary and must pass appropriate review before a stable professional learning release.

## Identity and alignment

The overlay preserves the existing lexical, sense, category and discovery-group IDs. It does not create a second English meaning or a second illustration/recording merely because a translation is available.

Each entry records its expected `sourceWord`. Translated examples and collocations record the exact English text next to `translation`, so the application can match by source text rather than relying on array positions after publication filtering or reordering. The two pressure senses remain `pressure:blood-pressure` and `pressure:force-per-area`; their medical and engineering examples retain their original meaning associations in the English release.

Definitions, glosses and usage notes are in the learner’s selected language. The existing source release supplies the English definitions, lexical metadata, CEFR levels, relationships and licensed English pronunciation recordings. English speech is still English; Portuguese interface support does not turn it into Portuguese pronunciation instruction.

## Build the published locale snapshot

The browser imports `src/locales/published/pt-BR.json` or `src/locales/published/es-419.json`, generated by `scripts/build-locales.mjs`. It must not import the raw authoring overlay. Build the English/Persian release first, then compile the locale against that exact published release:

```sh
npm run build:content
node scripts/build-locales.mjs
node scripts/build-locales.mjs --check
node --test scripts/locale-release.test.mjs
```

The CLI builds or checks both supported vocabulary locales. The locale compiler follows `public/content/current.json`, verifies the manifest, compact index and entry-shard hashes, and reads only those published artifacts. It filters translations to published lexical and sense IDs, binds examples and collocations to exact published English, and emits only explicitly allowed display fields. Draft/withdrawn translations, unavailable meaning/example translations and unknown authoring metadata do not enter the generated snapshot. An unscoped usage note is omitted if some of its translated meanings are excluded. The source release identity and manifest hash accompany the generated preview.

The check command fails if the tracked snapshot differs from the current compiler output. Regenerate it after changing source content or translations, and inspect the resulting diff. Do not hand-edit the generated snapshot. The compiler does not make network or generation-service calls, and no translation approval is inferred from a successful build.

## Editorial review

Keep `status: "preview"`, `humanReviewed: false` and `aiAssisted: true` until actual review occurs. Review translations against the exact English text, illustration and selected sense. Record reviewers and revision evidence honestly; a successful structural check does not establish linguistic or domain approval.

The locale overlays are not yet separate stable publisher channels with its own signed review records. That work should bind future approvals to the translation revision as well as the source revision before any stable claim is made. Adding review flags alone is not review.

When source content changes, check that the referenced lexical and sense IDs still mean the same thing and that all exact-English bindings still match. Add new translations explicitly instead of inventing text or displaying Persian as if it were the selected language. Subcategory translations also bind to exact English labels and compile in source taxonomy order, so missing translations cannot shift labels onto another subject.

Both editions now use the same full learning application as Persian: onboarding, daily study, FSRS review, Atlas, galaxy, reading, practice, settings and backups. UI guidance is localized through the shared shell; learner datasets, active sessions and reading state remain edition-specific. Existing saved words from the earlier Portuguese preview migrate into the full Portuguese dataset.

Reading, books, paraphrases and confusable exercises use separate source-bound overlays and a separate publication compiler. They are fully translated for the current starter catalog; see [localized reading and practice](localized-reading-content.md). These small starter collections and complete taxonomy labels do not imply a complete curriculum.

After changing reading overlays, run `npm run build:reading-locales` and `npm run check:reading-locales`. The `predev` and `prebuild` hooks run the English, vocabulary and reading compilers in that order.
